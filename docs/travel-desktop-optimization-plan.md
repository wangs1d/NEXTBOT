# 行程三端定位分工优化方案（桌面做减法 · 手机做加法）

> 2026-10-13 定调。核心判断：**桌面端是行程「阅读器」，手机端才是「实地引导」**。
> 凡是面向「人已经在路上」的实时过程功能，放在桌面端都是冗余设计——真实应用发生在手机端。

## 一、产品定位

| 端 | 角色 | 场景 | 设计原则 |
| --- | --- | --- | --- |
| 桌面端 `server/web/travel-map/desktop.html` | 行程**阅读器** | 行前规划查阅 / 事后回忆，信息消费（lean back） | 只呈现「计划态」：介绍、图文、地图总览。不做进行态 |
| 手机端 `travel_plan_mobile_page.dart`（原生页）+ `server/web/travel-map/mobile.html` | **实地引导** | 人在现场，实时跟随（lean forward） | 承载全部过程功能：跟随、信号重排、到达动线、导航 |

推论：桌面端「当前所在 / 节奏追赶 / 跟随中」这类**进行态语义**要全部清掉或降级为静态展示；
重排决策（收站/加回/时间锚点保护）是 Agent 侧职责，桌面只被动呈现。

## 二、桌面端改动

### P0（本次明确要求，立即可做）

| # | 改动 | 位置 | 说明 |
| --- | --- | --- | --- |
| 1 | **删除左下角「我」图标** | `desktop.html` L264 `.avatar` + L69 样式 | 桌面端无账号/个人中心语义，纯装饰占位。连同 `.side-spacer` 一起清（spacer 只为把它推到底部） |
| 2 | **右下角加 `<` `>` 站点跳转按钮** | `view-now` 主视图右下角，新增 `.stop-nav` 浮层 | 上一站/下一站调用已有 `setCur(cur±1)`，端点置灰；中间显示「3 / 10」站序。与右栏列表、旅程带天然联动（同一 state.cur） |

### P1（进行态语义清理——本次定位分工的落地主体）

| # | 现状 | 问题 | 处置 |
| --- | --- | --- | --- |
| 3 | 顶栏「Agent 跟随中」chip（L284） | 「跟随」是实地进行态，桌面无人被跟随 | 删除，或改为静态「行程手册」角标 |
| 4 | Agent 气泡的「撤销」按钮（L325） | 撤销重排是实地操作语义 | 删按钮；气泡保留为「Agent 决策说明」展示 |
| 5 | 桌面端自动重排启发式（`rainHides`/`tiredHides`/`replan` 收站） | 收站决策属 Agent/手机端；桌面按文本猜「下雨收站」是越权臆造 | 降级为纯展示：`optional` 站始终入列、进「备选」区，不做事件触发收站；`applySignal` 到达时仍可被动呈现 Agent 的结论 |
| 6 | 备选站按钮文案「现在就去」（L615） | 实地出发语义 | 改「加回行程」 |
| 7 | 旅程带 `mood`「今日节奏 · 追赶中」 | 节奏追赶是过程态 | 真实载荷下本就不编造；演示态文案保留即可，真实模式仅显示结束时间 |
| 8 | 地图站点 `pulse` 呼吸圈（`.poi.now .pulse`） | 呼吸圈表达「当前人在此」，桌面无定位 | 改为静态高亮（去动画），保留选中态描边 |

### P2（可选打磨）

- 「建议停留」进度条 → 静态时长文本（进度条暗示计时进行中）。
- 演示数据 `DEMO` 精简：宿主形态已不展示演示数据，可把演示数据压缩到最小集，降低包体与维护面。
- `rb-alt` 区头文案「节奏松下来会自动加回」是过程语义，改「备选安排」。

### 桌面端保留项（阅读态的正当职能，勿误删）

- 大图 + 介绍 note + `/travel-poi/details` 补图补 wiki（`enrichLive`）——行程介绍的强化。
- 照片预热 `preloadDayAssets`、Day 胶囊条、地图总览 + 真实路网连线 + 路线图例。
- 旅程带作为全程结构图（选中段高亮，弱化 done/now 时间语义）。

## 三、手机端补强（加法）

设计版式以 `docs/design/mobile-travel-agent/` 定稿为准，**动 UI 前先查，禁自拟版式**。

| # | 能力 | 现状 | 方案 |
| --- | --- | --- | --- |
| 1 | **外部导航唤起**（P1） | `_ArriveFlow` 只有到达动线描述，全页无 geo/amap/launch 调用（已核实 2725 行无关键词） | 「前往下一站」按钮追加「导航」动作：Android `geo:lat,lng?q=…` intent，iOS `MKLaunchOptions`/通用地图 URL，坐标用 entry 经纬度。拿不到坐标时按钮不出现，不编造 |
| 2 | **我的位置上地图**（P1） | `_RouteMapOverlay` 只有站点标记，无用户位置 | 请求定位权限，「我的位置」画进路线 overlay，显示「距下一站 X m · 步行约 Y 分」（直线距离诚实标注，不假装是路网） |
| 3 | 到站感知 / 自动推进 | 走 Agent 侧 signal 通道（`PA_TRAVEL_SIGNAL` / `applySignal`），前端被动 | 维持现状：前端只呈现，定位感知结论由 Agent 侧推送 |
| 4 | 节奏反馈、实时信号 | 已是手机端专属（2026-10-12 从桌面整体移交），原生页有 `_SignalHint`/`_GhostButton` | 不动 |

## 四、分工终态一览

| 功能 | 桌面 | 手机 |
| --- | --- | --- |
| 行程介绍（图文/wiki/实拍） | ✅ 主职责 | ✅（站点详情页） |
| 地图总览 + 真实路网 | ✅ | ✅（按需呼出） |
| Day 切换 / 全程抽屉 | ✅ | ✅ |
| 上一站/下一站跳转 | ✅（本次新增 `< >`） | ✅（一屏一站滑动） |
| Agent 跟随 / 信号重排 | 展示结论（被动） | ✅ 实时承载 |
| 节奏反馈 / 收站加回 | ❌（只展示备选） | ✅ |
| 外部导航 / 我的位置 | ❌ | ✅（本次补强） |

## 五、验收口径

1. `desktop.html`：左栏无「我」头像；右下角 `< >` 可循环/置灰切站，与右栏、旅程带、地图 marker 三方联动。
2. 桌面进行态清理后：真实载荷下页面不再自动收站（备选只展示）；「撤销」「现在就去」「跟随中」不再出现。
3. 手机端：native 页新增导航唤起与我的位置，版式改动不超过 `docs/design/mobile-travel-agent/` 定稿范围；`dart analyze` 零新告警。
4. 契约不破：`server/test/travel-map-routes.test.ts`（UA 分流 + 桌面标识）与 `travel-plan-agent-loop.test.ts` 照常通过；`server/web/**` 新提交记得 `git add -f`（.gitignore 覆盖）。
