# Goal 混合架构 · 前后效果对比

> 由 `server/scripts/compare-goal-arch.ts` 实跑生成（零 LLM 调用，全部确定性断言）。
> 复跑：`cd server && node --import tsx scripts/compare-goal-arch.ts`

## 一句话

改前：goal 只活在后台（对话面零感知）、拆解只活在模型脑子里（前端零事件）、
「跑完步骤」就等于「办成了」、执行失败只写日志。
改后：goal 每轮进对话面（69 tok）、拆解是执行中写下的可见步骤、达成要过验收、
失败必开口、连续失败会冻结、同类目标第二次不花 token 拆步。

## 结构性变化（表格之外）

| 维度 | 改前 | 改后 |
|---|---|---|
| 时间尺度 | 轮次 / Goal 两极 | 轮次 / TaskPlan / Goal 三层 |
| 拆解触发 | 路由闸门猜复杂度（默认关） | 执行压力（≥3 次工具调用且无 plan） |
| 达成判据 | `every(step.done)` | 确定性验收（+ 可选语义终审） |
| 失败处置 | `blocked` 静默 | 成本类静默 / 执行类必开口 |
| 调度节奏 | tick 5min + 每目标 10min 强推 | tick 30min + `nextEligibleAt` 退避 + 失败冻结 |
| 成本可见性 | 只有全局 token | `/api/proactivity/goals/cost` 按 kind 归因 |
| 能力沉淀 | 无 | 模板库（成功流程 / 失败规避 / 操作偏好） |
| 台账 | 两套并行 | 一张只读统一视图（承诺暂不迁表） |

## 实跑数字

| 场景 | 改前 | 改后 | 变化 |
|---|---|---|---|
| 有在办目标的对话轮 | prompt 里没有【在办目标】块 →「那事怎么样了」只能靠记忆模糊召回 | 注入【在办目标】109 字符 ≈ 69 tok，可直接答「2/5 步，当前在比价机票」 | +109 字符/轮（≈69 tok） |
| 闲聊轮（1 次工具调用） | 不拆、无 plan | 不拆、无 plan（压力 1 < 阈值 3，0 次提示、0 tok） | 0 |
| 复杂轮（4 次工具调用） | 拆解只活在模型脑子里，前端 0 个步骤事件 | 波末软提示 1 次 → plan.write → 4 个 plan_step 事件（s1:pending, s2:pending, s3:pending, s1:running） | +1 次提示（约 44 tok）、+4 个事件 |
| 步骤全 done 但没留下产物 | 旧判据 every(done)=true → 标记 ready、「搞定了」 | 确定性验收=partial → 不宣布完成：「有 2 步没留下结果，无法确认「机票酒店都定下来且预算内」是否达成」 | 假完成 0 次 |
| 执行类失败（验收没通过） | blocked 只写日志、不打扰 → 用户永远不知道卡住了 | 发 1 条提案：「计划「订三亚行程」卡住了」— 「比价机票」推不动：验收没通过：有 1 步没留下结果，无法确认「机票定下来」是否达成。你看怎么处理？ | 失败必开口 |
| 连续 2 次失败 | 每 10min 继续重推（同一失败反复烧 token） | 首次失败退避 2h；连续 2 次冻结（eligible=false），转「卡住了」 | 停止无谓重试 |
| 同类目标第二次（旅行） | 每次都要模型现场拆步（一次 pro 调用，实测千级 input tok） | 命中模板 travel → 直接 6 步 + 自带达成判据（0 tok 拆步） | 省 1 次规划调用 |
