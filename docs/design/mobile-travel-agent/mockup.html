结构 · 一屏一站

  • 弹性旅程带：每段宽度 = 停留 + 交通时长，Agent 调速时平滑伸缩，收起的备选渲染为虚线段
  • Now 主卡：实拍大图 → 时间档（锚点显式标注）→ 安排理由 → 建议停留进度 → 下一站条
  • 底部拇指区：主按钮直达下一站（含交通方式与分钟数），副按钮呼出路线地图
  • 站点切换点：卡片下方圆点指示当天站点位置，可左右点位快速跳站

交互契约（前端只呈现）

  • PA_TRAVEL_SET_PLAN(plan) 注入每轮规划，整页重渲染
  • PA_TRAVEL_SIGNAL(ev, note) —— Agent 侧感知到「慢了 / 下雨 / 累」后推入，页面只被动重排（无手动上报）
  • PA_TRAVEL_REQUEST_ALT(id) 请求把 Agent 收起的备选站加回
  • 时间锚点由 Agent 侧保护，页面不自行改动已锚定时间

落地映射 · 本仓

  • 已落地 server/web/travel-map/mobile.html，与桌面 panel.html 同路由域，按 UA 分流；强制移动版 /travel-map/mobile
  • 取数三路：?planId= 读服务端真实行程仓库 GET /travel/plans/:planId（手机端默认）· ?id= 读内存载荷 · ?host=1 由宿主桥注入
  • 载荷 days[].items[]（仓库）/ days[].entries[]（内存）→ 本设计 stops[] 一层适配：绝对分钟、停留时长、坐标、站间交通方式
  • 地图复用已有 /travel-basemap/style/dark 瓦片代理；站点无自带图时按需取 /travel-poi/details 真实实拍；无坐标回落 SVG 动线

状态与边界

  • 空态：未注入规划时整屏是「等待 Agent 规划」，不显示假数据
  • 备选：Agent 主动收起的站进「可请求加回」，不直接消失
  • 节奏标签：刚刚好 / 很从容 / 比较充实 / 追赶中 / 雨天室内 / 省力模式
  • 实时信号：由 Agent 侧感知（步速 / 位置 / 天气 / 对话）后经桥推入，页面无手动上报控件
  • 本稿数据全部来自服务端真实行程仓库（plan-data.js 由 tools/build-plan.mjs 生成），图片为真实 POI 实拍
