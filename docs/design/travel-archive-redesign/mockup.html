1解决的痛点

  • 平铺无层次：进行中 / 未开始 / 已结束行程视觉权重完全相同，一眼抓不到重点
  • 辨识度差：68px 小封面 + 三行小字，卡片同质化，靠读文字找行程
  • 不可管理：无搜索、无筛选、无删除，行程变多后只能无限滚动肉眼扫

2「时间漏斗」信息架构

  • 进行中 → 英雄卡置顶：大封面 + 「Day x/y」进度徽章 + 「继续行程」直达按钮（服务端 progress API 已有，直接可用）
  • 即将出发 → 中卡 + 倒计时：「还有 N 天」本地日期计算，强化期待感
  • 往期回顾 → 紧凑行收纳：小图行式布局，弱化为档案视角，按时间倒序
  • 顶部 chips（全部/即将出发/往期回顾）+ 搜索 = 两级快速定位，≤20 条本地过滤零延迟

3交互与视觉规则

  • 状态语义色：进行中=品牌绿（呼吸光点）、即将出发=浅绿底倒计时、已完成=灰
  • 点击行为不变：条目 → 拉完整行程 → 手机原生页 / 桌面 WebView 面板
  • 下拉刷新保留；空态 / 错误态沿用现有文案微调
  • 长按呼出管理菜单：置顶（本地）、分享码（服务端已有）、删除

4服务端依赖（新增，量很小）

REQUIRES BACKEND
  • DELETE /travel/plans/:planId：删除落盘行程（当前只有条目级删除，无整体删除）
  • 列表接口 GET /travel/plans 追加返回 progress 摘要（day/stop），英雄卡免二次请求
  • 置顶仅存客户端本地偏好，不动服务端
