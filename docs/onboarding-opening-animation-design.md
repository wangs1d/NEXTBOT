# 首次启动引导与开场动画方案（设计稿，未实现）

> 状态：方案设计阶段。本文档不含代码改动，仅供评审。
> 日期：2026-09-05

## 1. 目标流程总览

```
首次启动（本地无 onboarding.completed 标记）：

  启动 → [声音选择页] 赋予TA一个声音（男/女，可试听）
       → [开场动画] 黑底 + 白光逐渐绘制图案（约 4s，可跳过）
       → 进入主界面，白光图案"点亮"为情感球，主界面淡入
       → 问候语音：「你好，我在这，以后我就是你的私人管家」　← 峰值①
       → [双向命名] 管家先问用户称呼 → 用户给管家起名 → 管家念出双名（两步均可跳过）
       → 能力点亮：白光扫过侧栏，图标依次亮起（获得感具象化）
       → [觉醒卡] 生成可保存/分享的关系凭证 + 写入第一条记忆　← 峰值②/结尾
       → 写入 onboarding.completed，之后不再出现

非首次启动：

  启动 → [回归动画] 简短版（约 1.5s）：白光快速勾勒球轮廓 + 管家名字淡现
       → 直接进入主界面（不播语音）
```

## 3. 页面一：声音选择页（仅首次）

**定位**：开场动画前的必要步骤，黑色主题与主界面一致。

- **布局**：居中标题「选择我的声音」，下方两张大卡片并排 —— 「男声」「女声」，卡片带微光呼吸边框；底部一个「就这样，开始吧」确认按钮。
- **交互**：
  - 点击卡片即试听（不切换选中态，试听与选中分离，试听词 = 正式问候语开头「你好，我在这。」，让用户听到什么、之后就是什么）。
  - 单击选中（卡片高亮），再次点击同一卡片可重复试听。
  - 未选中时确认按钮置灰。
- **试听音频来源**：调用服务端 TTS 即时合成（同一 voiceId），首次点击可能有 1~2s 合成延迟，期间卡片显示加载微光；可选优化：进入页面后预合成两句试听词。
- **降级**：无网络/合成失败时，试听按钮置灰，仅保留选择功能，不阻塞流程。
- **提交时同时做两件事**：本地写 `onboarding.voiceGender`；向服务端上报偏好（见 §7）。确认后**立刻请求服务端预合成完整问候语 mp3**，开场动画的 4 秒正好掩盖合成延迟，进主界面即可零等待播放。

## 4. 页面二：首次开场动画

### 4.1 画什么（推荐：球体图案，文字为副元素）

推荐绘制一个**光的球体轮廓**（圆环 + 收笔时中心一点亮起），理由：

1. 与主界面中央的情感球形成叙事闭环——白光画完的球，就是进入主界面后"点亮"的那个球，动画不是孤立装饰，而是"管家被唤醒"的过程。
2. 几何简单，纯代码绘制即可，无需设计资源。
3. 用户起的名字可以在球下方淡现一行小字（副元素），回归动画里它 becomes 主角。

备选：绘制产品名/单词文字路径。技术上同样可行（见 4.2），但与产品叙事关联弱，且中文字形笔画多，描边动画排序需要额外处理。

### 4.2 技术选型

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. CustomPainter + PathMetrics（推荐）** | `TextPainter.getOutlinePath()` 或手绘 Path 得到轮廓，`PathMetric.extractPath(start,end)` 画出部分长度；笔尖光点 = 白色圆 + `MaskFilter.blur` 辉光 | 零新依赖，与现有 entrance_animation 同风格；无 WebView 冷启动延迟；结尾与 Flutter 层情感球同层过渡最自然 |
| B. WebView + SVG stroke-dashoffset | 复用 emotion ball 的 host.html 字符串注入管线，SVG feGaussianBlur 辉光滤镜效果好 | WebView2 冷启动有黑屏延迟风险；动画层与情感球分属两个渲染层，交接生硬 |
| C. Lottie / Rive | 引依赖 + 外部设计资源 | 需要设计师产出，违背"代码即可画"的轻量目标 |

选 A。若未来要画复杂图案（logo 手写字等），A 的 Path 也可以从 SVG path data 导入，不必换框架。

### 4.3 时间轴（总长约 4s）

| 时间 | 画面 | 声音 |
|---|---|---|
| 0 – 0.4s | 全黑，中心一个极微弱的光点 | （静） |
| 0.4 – 2.6s | 白光从光点出发，沿路径逐渐画出球体圆环（笔尖带辉光，线条尾迹渐隐） | 可选极轻的合成音/环境音（后续再加） |
| 2.6 – 3.2s | 圆环闭合，光沿环收敛一圈，注入中心，球心亮起并开始呼吸 | （静） |
| 3.2 – 3.8s | 球体轻微缩小并"落位"，主界面淡入，球与情感球位置重合（视觉上同一个球） | **问候语音开始播** |
| 3.8s 起 | 命名卡片在球下方浮现（见 §5） | 问候语约 3~4s |

- **跳过**：点击任意处立即完成全部状态、直接进入主界面（问候语照常播，不因跳过而丢失）。
- **可重播**：设置里加「重播开场动画」入口（方便调效果，也满足用户情怀）。

### 4.4 交接细节

现有 EntranceAnimation 是每次启动播的旧动画，本方案上线后它改为**仅作为回归动画的底稿被替换/重构**（见 §6），避免首次用户连看两段动画。开场动画结尾球落位的坐标，取 chat_page 情感球的实际布局位置（Stack 内 Positioned 区域中心），保证"落位即归位"。

## 5. 问候与命名环节

- **形式**：主界面 chat page 上叠一个 onboarding overlay（背景半透明暗化，情感球保持可见点亮）。问候语播放的同时，聊天流写入第一条管家消息「你好，我在这，以后我就是你的私人管家。」——听觉与视觉双通道，且这条消息留在会话历史里。
- **命名卡片**：问候语播完后（或播完 0.5s 后）浮现：
  - 标题「给我起个名字吧」+ 输入框（限长，如 12 字符）
  - 2~3 个建议名一键填入（建议名单作为常量可配）
  - 「先这样叫我」跳过按钮 → 不取名（各处显示「未命名」，之后可随时改）
  - 提交后：卡片收起，管家**语音回应**：「（名字），收到，以后请多指教。」（现场合成，失败则仅显示文字），聊天流追加一条确认消息
- **名字的去向**（重要）：
  1. 本地 KV：`agent.butlerName`
  2. 客户端 UI：侧栏/档案页的 `_agentName` 显示
  3. **服务端人设**：目前整条 prompt 链路没有名字占位符，需在 `prompt-context-builder.ts` 的人格片段中注入「用户为你取名『XX』」。不做这一步，命名就只是个 UI 贴纸——管家对话中不知道自己叫什么。这是本方案里唯一需要新增服务端逻辑的点。
- **命名可修改**：解锁档案页 displayName 的只读限制（或提供"重新命名"入口），改名后同样走本地 + 服务端两条链路。
- 情绪升级：命名建议做成**双向命名**仪式（管家先问用户怎么称呼），详见 §10.2。

## 6. 非首次：回归动画

- **时长约 1.5s**：黑底 → 白光快速描一个圆（不画满，收笔即止）→ 圆心亮起 → 整体淡出进主界面。已命名的用户，名字在圆下方淡现 0.5s 后随黑幕一起退去。
- **不播语音**：桌面应用重启频率高，每次语音问候会迅速变成打扰。回归动画默认无声（后续可留一个"每次启动都打招呼"的设置开关，默认关）。
- **实现**：与首次动画同一个绘制器组件，参数化（时长、是否画满、是否带名字、是否接问候流程）。替换现有 `entrance_animation.dart`，而非并存两套。

## 7. 数据与状态设计

**本地 KV**（`IsarLocalHistoryStore.getPreference/savePreference`，随主存储 JSON 落盘）：

| 键 | 类型 | 说明 |
|---|---|---|
| `onboarding.completed` | bool | 首次流程是否完成，启动分流依据 |
| `onboarding.voiceGender` | `'male' \| 'female'` | 声音选择结果 |
| `agent.butlerName` | string | 管家名字（空 = 未命名） |

**服务端**：

- 声音性别偏好上报到 user-preferences（新增字段如 `ttsVoiceGender`）。
- **打通音色**：`tts-service.ts` 的 `synthesizeMp3*` 增加 voiceId 参数（从请求上下文/用户偏好读取），适配器层已支持 `options.voiceId`，只差透传。所有 TTS 出口（主动语音、电话、命名回应）统一生效。
- **持久化坑**：`user-preferences.ts` 的 `prefsStore` 是内存 Map，**服务重启即丢**。声音偏好和管家名字若只存服务端会丢，因此本地 KV 是 source of truth，服务端作为对话人设的消费端；顺手应把 user-preferences 落盘（独立小任务，可从本方案拆出）。

## 8. 边界情况

| 场景 | 处理 |
|---|---|
| TTS 合成失败 / 无网 | 问候与命名回应静默降级为纯文字；动画本身纯本地，不受影响；试听按钮置灰但流程可走完 |
| 用户跳过动画 | 点击即完成，状态直接就绪，问候语照播 |
| 合成延迟 > 动画时长 | 进主界面后问候语晚到晚播，命名卡片等问候播完才出（即自动顺延），不会出现文字卡片和声音抢拍 |
| 首次标记已写但命名被跳过 | `agent.butlerName` 为空，各处显示「未命名」；下次启动正常走回归动画 |
| 音频设备不可用 | audioplayers 已有容错，播放失败仅记日志 |
| 流程中断（首次动画中途退出应用） | 标记未写，下次启动重新进入引导；声音选择已提交的可记住（`voiceGender` 先于 `completed` 落盘） |

## 10. 情绪设计：把首跑流程做成一场「唤醒仪式」

目标：流程结束时用户带走三样东西——一个**物**（觉醒卡）、一个**关系**（双向命名）、一句**金句**。获得感来自具体的物，社交货币来自可分享的卡与可引用的话，情绪来自"黑 → 光 → 声"的对比节奏。

### 10.1 情绪曲线

```
静默(全黑) → 好奇(白光画球) → 惊喜(球点亮+第一声问候，峰值①)
→ 参与(交换名字) → 获得感(能力点亮+觉醒卡浮现，峰值②) → 余韵(保存/分享)
```

峰终定律：体验被记住的是峰值和结尾。峰值①交给"第一声问候"（声音是最快唤起情绪的通道）；结尾交给"觉醒卡"——它同时是获得感与社交货币的载体。

### 10.2 逐拍强化建议

| 拍 | 基础设计 | 情绪强化 |
|---|---|---|
| 声音选择 | 两张卡片选男/女 | 文案改为「赋予 TA 一个声音」；卡片内用白色光纹波形微动（男声低频 / 女声高频，CustomPainter，零素材）；确认时被选卡片亮起、另一张隐去——把"偏好设置"变成"塑造一个生命"的参与感 |
| 唤醒动画 | 光画球 + 点亮 | 球心亮起瞬间加一声极轻的低频"唤醒音"（仅首次动画；回归动画保持无声） |
| 第一声问候 | 你好，我在这，以后我就是你的私人管家 | 保持不动，这就是峰值① |
| 命名 | 用户给管家起名 | 升级为**双向命名**：管家先问「我该怎么称呼你？」→ 用户输入自己称呼 → 管家念出双名：「XX，你好。我是 YY，以后我们互相照应。」名字交换 = 关系成立的仪式（两步各自可跳过） |
| 能力点亮 | （新增拍） | 命名完成后 1~2s，白光从球体流向左侧栏，日程/消息/记忆等图标依次亮起一遍——"看，你得到了什么"比"设置完成"的获得感具体得多 |
| 收尾 | （新增拍） | **觉醒卡**浮现（见 10.3）；同时把「2026.09.05，我们认识了，TA 叫 YY」写入记忆系统作为第一条记忆——命名时刻成为可被长期引用的关系锚点（"还记得我们第一次见面吗"） |

### 10.3 觉醒卡（社交货币的核心载体）

- **形态**：黑底白光卡片，与开场动画同一视觉语言：光之球图案 + 管家名字 + 用户称呼 + 唤醒日期时间 + 唤醒编号（如 `唤醒编号 20260905-2147`，由本地时间生成，真实不造假；未来服务端若有序号接口可换全局编号）+ 声线属性（如「声线：沉静男声 · 初始形态：光之球 · 待解锁能力：7/7」）。
- **生成**：纯客户端 `RepaintBoundary → PNG`，无需服务端。
- **去向**：一键"保存图片"（Windows 存 Pictures + 复制剪贴板，可直接粘贴给微信好友）；卡片常驻档案页「我们的开始」入口，随时重看——一次性仪式变成持久所有物。
- **长期钩子**：唤醒日期入记忆；周年/满月时管家主动提起（proactive 体系已有，属后续迭代）。

### 10.4 文案即社交货币

收尾金句候选（管家最后一句，目标是被记住、被引用）：

- 「从现在起，你的事就是我的事。」
- 「我在，随时。」
- 「记得找我，我一直在。」

### 10.5 护栏：哇 ≠ 长

加入以上各拍后，首跑全程仍需控制在 1 分钟内（选声 10s → 动画 4s → 问候 4s → 双向命名 15s → 能力点亮 2s → 觉醒卡 5s），每一拍可跳过，不新增注册/登录等任何摩擦项。惊喜来自节奏与对比，不来自时长。

### 10.6 实现成本注记

觉醒卡、波形卡片、能力点亮全部为客户端本地实现；唯一跨端点是记忆首条写入（agentic-memory ingest 已存在）。无新增服务端接口。
