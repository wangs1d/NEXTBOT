SCREEN 01 · 首页

先处理，再浏览

进入动态 tab 第一眼看到的是「要做什么」，而不是「有什么」。未读横幅只在有新增时出现，看过后消失。

  • 待处理队列：快递 / 还款 / 审批 / 异常，最多 3 条，行内直接给动作。

  • 未读：本地记录上次查看时间，按条目时间差计算「新增 N 条」，底栏同步徽标。

SCREEN 06 · 管理与拦截

真实状态 + 来源规则 + 稍后提醒

「数据源」不再是写死的说明，而是真实读取通知使用权与邮箱监听状态；低价值消息不折叠，直接在入口层拦截，只保留可审计的计数。

  • 真实状态：通知使用权、邮件监听、最近同步时间，失败时给「去开启 / 去配置」。
  • 来源规则：高优先 / 正常 / 免打扰 / 不进入，按来源配置。
  • 拦截统计：本周拦截条数按类型拆分，可进入明细核对，但不展示正文。
  • 稍后提醒：底部弹层，1 小时 / 明天 9:00 / 本周末，服务端存 snoozeUntil。
实现说明字段、接口与状态口径

台账新增字段

  • pickedUpAt?: number|null：快递已取件时刻；待取 = 有取件码且为空。
  • billStatus?: "reimbursed"|"wrong"|null：已报销 / 记错了。
  • snoozeUntil?: number|null：稍后提醒到点时间。
  • pinned?: boolean / archivedAt?: number|null：置顶与归档。
  • subscription?: { name, cycle, amount, nextChargeAt, chargedCount, suggestion }：续费识别结果。
  • duplicateOf?: string：同商户同金额疑似重复时指向原条目。

接口

  • POST /api/dynamics/parcels/:id/pickup {pickedUp}
  • POST /api/dynamics/bills/:id/review {status: reimbursed|wrong|clear}
  • POST /api/dynamics/entries/:id/snooze {until}
  • POST /api/dynamics/entries/:id/pin|archive
  • GET /api/dynamics/subscriptions / POST .../:id/dismiss
  • GET|PUT /api/dynamics/source-rules
  • GET /api/dynamics 增加：bills.reimbursedCount / wrongCount、parcels.pickedUp、subscriptions、sources、blockedThisWeek

状态与口径

  • 待取件：有取件码且 pickedUpAt 为空；已取件不计入首页待取与徽标。
  • 记错了：从近 30 天合计、分类占比中扣除；列表保留并显示删除线。
  • 已报销：金额仍计入合计，单独统计笔数。
  • 疑似重复：同商户 + 同金额 + 48 小时内 ≥2 笔，仅提示不自动删。
  • 订阅：账单/短信命中「连续包月 / 自动续费 / 每月」等关键词，且近 90 天 ≥2 次同额扣款。

低价值拦截（入口层）

  • 验证码：MailWatch 整封丢弃，/api/dynamics 再兜底过滤。
  • 营销推广：命中「退订 / 促销 / 优惠券 / 活动」等关键词的短信与通知不落台账。
  • 重复物流：同单号多次更新只在轨迹里累积，动态页只保留一条。
  • 群聊通知：默认不进动态页，来源规则可单独开启。
  • 可审计：只回 blockedThisWeek 计数与分类，不展示正文。

交互细节

  • 动作后局部更新 + 顶部 3 秒「撤销」，返回首页静默刷新。
  • 多选：长按进入，底部黑色操作条，退出清空选择。
  • 滑动：左滑归档、右滑完成，仅列表页启用。
  • 失败：卡片内联错误 + 重试，不整页报错。
  • 未读：本地记录上次查看时间，按条目时间差计算；进入即清零。

其余已确认能力（增量）

  • 按实体聚合：商家 / 发件人 / 承运商卡片，点入看该实体全部动态。
  • 物流轨迹折叠：同单号多次更新合成一条，详情页展开轨迹。
  • 消息日历 / 热力图：按天看消息量与类型分布，作为首页顶部切换视图。
  • 卡片问 Agent：带上当前实体上下文跳转对话（本稿已在账单详情落地）。
  • 小组件 / 月度报告 / 导出：待取件数与今日支出上桌面；账单 CSV 与报销单导出。
  • 日程与审批联动：到站提醒加日程、审批一键通过。

落地顺序建议

  • 第一批：待处理队列、今日摘要（模板）、未读与底栏徽标、时间分组、搜索筛选。
  • 第二批：已取件 / 已报销 / 记错了动作闭环 + 台账字段与接口。
  • 第三批：订阅与续费扫描、疑似重复检测。
  • 第四批：来源规则、稍后提醒、归档/置顶、拦截统计。
  • 第五批：数据源真实状态、问 Agent 上下文入口。
