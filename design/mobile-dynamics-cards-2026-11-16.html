设计稿 v1

先回答数据问题：不是没接入，链路是通的。服务端 /api/dynamics 已注册，账单/快递来自 BillParcelLedger（手机通知、短信、邮件三路上游汇入），提醒/足迹来自 AttentionStore / AgentActivityStore，邮件要事来自 SourceStore 的 mail 流。 页面看起来“没有数据”，通常是上游没有产出：Android 通知使用权未开启、邮件监听未配置、或 30 天窗口内确实没有识别到条目； 另外当前页面所有卡片都没有点击行为，只是平铺展示。 本稿把汇总卡与四类信息卡都改成“表面即数据、整卡可点进详情”的形态。

已接入

服务端聚合与落库都在

通知/短信 → MessageHub → BillParcelIngest → 台账；邮件 → MailWatch → 同一台账。 路由在 index.ts 无条件注册，缺数据源时返回各区块空数组，接口恒 ok:true。

为什么像没数据

上游产出有前提

  • 通知使用权未开启 → 短信/菜鸟/银行通知进不来
  • MAIL_WATCH_ENABLED 默认关闭，需 IMAP 账号
  • 汇总窗口是滚动 30 天，不是自然月
  • 页面 20s 超时或服务端不可达 → 落错误态
本稿改动

从“看一眼”到“点进去”

  • 汇总卡直接显示最新一条摘要，整卡可点
  • 每类信息收成一张聚合卡：最近 2 条 + 查看全部
  • 新增快递 / 账单详情页，字段一一对应
  • 空态给出数据源状态与去开启入口

实现规格与字段映射

现有接口已够支撑本稿；详情页建议直接复用列表项对象，不额外请求。

卡片 → 接口字段 → 交互

区域数据点击行为
汇总 · 账单 bills.count / bills.totalAmount 账单列表 → 单条详情（传 item）
汇总 · 快递 parcels.awaitingPickup / parcels.latestPickup 快递列表 → 单条详情
快递卡 parcels.recent[]：pickupCode / carrier / trackingNo / occurredAt 整卡 → 快递列表；单行 → 详情
账单卡 bills.recent[]：title / amount / billType / source / occurredAt 整卡 → 账单列表；单行 → 详情
提醒卡 alerts.pending[]：title / summary / urgency 复用现有提醒详情 / 对话定位
邮件卡 mail.recent[]：title / text / at 邮件详情（已有邮件模块）
足迹 alerts.activity[]：title / summary / statusLabel 可选：折叠在“更多动态”里

交互与状态

  • 整卡可点：InkWell 包整张卡，按下态 0.55 透明；右侧 chevron 只做提示，不单独响应。
  • 下拉刷新：保留现有 RefreshIndicator；静默刷新失败不清空已有数据。
  • 首屏：磁盘缓存先出（stale-while-revalidate），再静默换新，避免转圈。
  • 加载态：首屏无缓存时用骨架卡（3 张灰条），不用整页 spinner。
  • 超时：20s；错误态保留“服务端地址 + 重试”，和现有实现一致。
  • 去重：台账已按单号/取件码去重，列表直接渲染，不再客户端合并。
  • 详情页数据：列表项已含 excerpt，直接带入；若做“全部列表”，请求 /api/dynamics?limit=50 后按 category 过滤。
