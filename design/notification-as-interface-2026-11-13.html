通知即界面 · 通知栏即决策面

把决策点和操作按钮直接放在通知栏，用户只在通知栏完成「拍板」这一个动作，剩下的由 Agent 自己做完并闭环。 本稿是 NEXTBOT 移动端（Android 通知栏）的设计定稿：文案结构、按钮语义、执行中与回执形态、内联回复、以及不可逆动作的降级路径。 同一套 actionId 同时渲染到聊天卡片与通知栏，通知栏只是第二个渲染面。

场景红线

NEXTBOT 只在互联网里有手。它能感知、能操作的对象全是数字对象——订单、票务、订阅、账号、额度、账单、日程、消息。 所以进通知栏的动作必须是互联网对象上的数字动作（取消续费 / 接受改签 / 退订单 / 扩容 / 复制取件码）。 物理动作一律不进通知栏：放快递柜没有 API、送上门要打电话、给邻居是线下——这类按钮 NEXTBOT 执行不了， 通知栏里出现一个按不动的按钮，比不出现更糟。

对象全是数字对象

订阅、航班、额度——每一条背后都有一个真的能调的接口。 通知栏里的按钮和后端工具调用是一一对应的，不存在「按了但执行不了」。

文案三段式：事实 / 变化 / 建议

第一行是已经发生的事实（不是 Agent 的寒暄），第二行是Agent 已经算好的方案， 让人不用点开就知道点下去会发生什么。

按钮最多 3 个，第一个是默认动作

主按钮用高亮描边，其余用弱描边。按钮文案是动作短语不是「选项 A/B」； 「取消续费 / 保留」用户不读文字也知道该按哪个。

来源orb 作为品牌锚点

通知图标是 NEXTBOT 的白色发光 orb，锁屏上一眼认得出是「它」在找你， 不是一个来路不明的系统弹窗。

原地不新弹一条，原卡就地改

点「接受改签」后不新推一条通知，而是把这条通知原地改成执行中 → 回执。 通知栏不会因为一次点击多出一条消息。

回执给结果 + 给退路

回执必须带可验证的事实（新航班号、出票状态、座位）， 并保留一条撤销——通知栏是低承诺环境，误触必须能退。

兜底用户不点，Agent 也要自己推进

通知是加速器，不是唯一入口。没人响应时 Agent 按自己的规则兜底， 并把兜底结果写进通知（「改签窗口已关，票务差价 ¥0」），而不是让事情烂在通知栏里。

幂等连点两次只执行一次

执行端点按 intentId 去重，重复点击返回同一次执行的结果， 不会重复扣款、重复出票、重复扩容。

内联回一句话，不是回一个选项

按钮解决枚举型决策（取消 / 保留），内联回复解决开放型需求 （「晚上八点提醒我」）。两者共存，按钮永远排在回复框上方。

L2不可逆动作不在通知栏执行

账单、支付、取消订单不放执行按钮，只给「去确认」—— 确认动作落到 App 内的面容 / 二次确认页。通知栏里明说「这笔钱我不能替你静默扣」， 把规则前置给用户看。

降级App 进程被杀时通知没有按钮

厂商离线推送（华为 / 极光）落地的是系统模板通知，带不了自定义按钮。 这时通知降级成「点开处理」——能力边界写清楚，别让用户面对一条点不动的通知。

有效期按风险分级，不统一 10 分钟

对话里的确认 10 分钟过期是对的；通知可能几小时后才被看到。 L0 给 24 小时，L1 给 2 小时，L2 不给有效期（过期即失效并撤通知）。

04

落地规范

可直接转成服务端 ActionIntent 字段与客户端通知构造
项规范说明
场景准入 只接互联网原生对象 订阅 / 票务 / 订单 / 额度 / 账单 / 日程 / 消息。物理动作（放柜、送上门、找人）一律不进通知栏
动作可达 每个按钮对应一个真接口 通知栏按钮与后端工具调用一一对应；没有接口的动作不许出现在按钮位
文案模板 标题 = 事实；正文 = 方案 + 关键约束 标题不超过 16 字；正文 ≤ 40 字，且必须包含「按下去会发生什么」
按钮数量 最多 3 个，第 1 个为主按钮 主按钮高亮描边；并排不超过 3 个，超出并入内联回复
按钮语义 动作短语，2–5 字 「取消续费」「接受改签」；禁止「选项 1 / 确定 / 取消」这类无信息按钮
风险分级 L0 可逆低风险 L1 会花钱可控 L2 不可逆 L0 通知栏一键执行；L1 一键执行 + 回执；L2 通知栏不放执行按钮，确认落到 App 内面容 / 二次确认
两个渲染面
已落地		 通知栏按钮 = 聊天气泡按钮 同一个 actionId ＋ 同一枚一次性 token，两处都渲染同一批动作。 气泡里是「需要你拍板」胶囊行（第 1 个实心为主按钮），通知栏里是系统 Action Button。 在哪儿拍板都一样，服务端只认一次（幂等）。
有效期 L0 24h · L1 2h · L2 无 过期撤通知并回一条过期说明，不静默作废
渠道配置 Android channel「主动提醒」importance=high 沿用现有 proactive 渠道；category=reminder；action 走 PendingIntent，API 31+ 必须显式 FLAG_IMMUTABLE
通知 id 按 intentId 哈希取模（三处同源） App 侧 LocalNotificationService、厂商侧 HMS notify_id、JPush 三处必须用同一个 intentId 哈希， 否则同一条决策跨层投递会出现两条通知
凭据 HMAC 签名的短期 token 不能用 deliveryId（d_+时间戳+序号，可猜）；action 端点验签 + 幂等 + 落审计
回执 原地改通知，不新推 回执带可验证事实（新航班号 / 出票状态 / 权益到期日）+ 撤销入口
兜底 未响应由 Agent 自己推进 通知是加速器不是唯一入口；兜底结果回写通知正文
