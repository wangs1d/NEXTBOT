跨端统一埋点出入口

一个事件模型、一个上报出口、一套事件登记。手机端与电脑端只调用同一层 track()，新功能接入不得各自造上报通道。
设计目标：① 使用习惯数据真实可查（拒绝估算冒充）；② 新功能零改后台即可进入统计；③ 手机 / 电脑口径一致，可横向对比；④ 上报失败不影响主流程（fail-open），隐私可关。

2统一事件模型（唯一契约）

所有端上报的事件必须是下列结构，缺字段直接拒收并记录原因。字段名跨端一致，不允许各端自定义别名。

// 统一事件信封 —— 手机端 / 电脑端 / 服务端三方共用
{
  event: "feature_use",        // 事件名：必须已在事件登记表登记
  ts: 1763714520123,            // 客户端毫秒时间戳（服务端不信任，仅用于排序）
  installId: "inst_9f2a...",      // 安装标识，复用现有 install_identity
  actorId: "acc_31c..." | null, // 账号 ID；未登录可空
  platform: "mobile" | "desktop", // 唯一枚举，服务端不靠 UA 猜
  appVersion: "1.8.3",
  sessionId: "s_7bd0...",        // 会话 ID，用于时长拼接与去重
  props: { "feature": "weather", "source": "chat" }
}
字段类型必填说明
eventstring是事件名，来自唯一登记表；后端未知事件名拒绝入库并告警
tsint64是客户端时间；服务端以 receivedAt 为准，两者差值用于识别时钟异常
installIdstring是复用 install_identity.dart，与启动埋点同一标识
actorIdstring|null否登录态才有；未登录行为计入设备维度，不混入账号留存
platformenum是mobile / desktop，二选一
sessionIdstring是一次前台会话一个；超时 30 分钟或切后台超时自动结束
propsobject否扁平 KV，值限 string/number/boolean；禁止嵌套与隐私字段

3标准事件清单（唯一登记表）

登记表是事件名与展示名的唯一事实源，集中在一处定义；后台功能偏好榜、时长、留存全靠它驱动。

事件名触发时机关键 props支撑指标状态
session_startApp 进入前台 / 桌面窗口激活—DAU、会话数新增
session_end切后台 / 关闭 / 超时durationMs使用时长新增
heartbeat前台每 60sactiveMs时长校正、防挂起虚增新增
feature_use任一功能实际执行feature, source功能偏好、下钻、新功能入榜新增
screen_view主页面切换screen路径分析（可选）二期
client_boot启动bootStatus, bootMs装机 / 启动（已有）已有
禁止：把用户聊天内容、标题、邮箱等隐私字段塞进 props；只能上报功能标识与计数类元数据。事件名一旦登记不得复用改义，变更走新增事件。

4端侧统一出入口（接线方式）

唯一 API：track()

两端只暴露这一个方法。业务代码不需要知道队列、批量、重试、鉴权细节。

// Flutter：业务侧调用示例
analytics.track(
  'feature_use',
  props: {'feature': 'weather',
          'source': 'chat'},
);
// Desktop：同一签名，同一事件模型
analytics.track('feature_use', {
  feature: 'weather',
  source: 'chat'
});
事件名校验会话自动注入本地队列批量上报失败补发隐私开关

出入口内部行为

  • 校验事件名是否在登记表；props 是否含禁报字段，不合法直接丢弃并计数。
  • 补全自动注入 installId / actorId / platform / sessionId / appVersion，业务无需传。
  • 入队写本地持久化队列（按序），绝不做同步网络等待；UI 零卡顿。
  • 上报批量 POST，达到 20 条或 30 秒触发；失败指数退避重试，重启后补发。
  • 降级连续失败超阈值停止重试并保留队列，不影响主流程；隐私关闭时只入内存不上报。

5新功能接线：3 步自动进统计

  • 第 1 步：登记事件在唯一事件登记表新增一行（如 event: "ai_draw"，展示名 AI 绘画），并声明关键 props。不新增字段、不改数据库表结构。
  • 第 2 步：端侧调用在功能真正触发处调用 track('ai_draw', { feature: 'ai_draw' })；手机端与电脑端各一行，签名相同。
  • 第 3 步：自动生效后台「功能使用偏好」榜按 feature 聚合，无需改任何后台代码即可出现新功能条目，并可按端 / 时段 / 人群下钻。
验收口径：新功能上线后，事件上报成功 → 概览功能偏好榜出现该条目 → 点击可看趋势与端分布。三步任一缺失视为接线未完成。

6服务端落库与聚合

事件表（追加写）

与现有 client-telemetry.db 同数据根，独立表 usage_events，追加写、不覆盖历史，按天分区滚动清理（默认保留 180 天）。

id自增主键
event事件名（带索引）
install_id安装标识（带索引）
actor_id账号 ID（可空，带索引）
platformmobile / desktop
session_id会话 ID（带索引）
props_json扁平属性 JSON
client_ts / received_at客户端 / 服务端时间

聚合口径 → 概览卡片

指标计算来源
每日上线率当日有效会话去重账号 ÷ 累计注册账号
使用时长session_end.durationMs 汇总 ÷ 活跃人数
功能偏好feature_use 按 feature count
留存率注册日后第 N 日有有效会话的账号占比
端分布会话按 platform 分组
时段热力事件 received_at 按星期 × 小时分桶
性能：5 分钟增量聚合写汇总表，概览接口只读汇总表不扫明细；明细表按天分区便于清理。

7边界与约束

真实性

埋点未上线前，概览相关卡片显示「统计中 / 暂无数据」，禁止用估算值或演示数冒充真实数据。上线后以服务端实际接收为准。

隐私与开关

提供用户级「匿名统计」开关；关闭时不落库。禁报聊天内容与个人身份信息，仅保留功能标识与计数元数据。

一致性

手机 / 电脑共用同一事件模型与登记表，未经登记的事件不入库；时间统一按 UTC+8 自然日分桶，服务端不依赖本地时区。

与现有约束对齐：服务端禁止 Date.now() / 无参 new Date()，一切时间走注入的 now()；事件落库的 received_at 必须由注入时钟产生，便于测试与多端时间口径一致。
