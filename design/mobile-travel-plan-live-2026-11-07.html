对齐结论：电脑端 desktop.html 已有的旅游规划展示能力（旅程带 / Now 卡 / 地图 / 时间轴 / 详情），手机端 Flutter 原生行程页已 1:1 落地，数据同走 /travel-plans 与行程卡载荷，口径一致。
唯一缺口：2026-10-18 上线的「页内连续导航会话」(/travel-map/nav/session + /travel-route 真实路网 + GPS 蓝点 + 到达/出发/跳过按钮) 只接在 server 网页版 desktop.html / mobile.html；Flutter 原生行程页的主按钮目前只是「翻到下一站」，没有接导航会话。手机端用户实际已无法走到 mobile.html（原生页替代了应用内浏览器路径）——按项目「新旧真实替换」铁律，这块能力需要接线到 Flutter，或确认砍掉。
