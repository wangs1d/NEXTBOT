# 2026-10-20

## 桌面端「托盘退出卡十几秒」根因修复（P0）

用户报：托盘菜单「退出」时进程特别卡。实测（`logs/exit-probe.ps1` / `exit-sampler2.ps1`）确认退出耗时 **19.57s**，期间 CPU 恒 0、87 个线程全 `Wait/Suspended`、WS 从 219MB 涨到 691MB，并出现 `WerFault.exe` 子进程。

**根因**：不是慢，是**每次退出都在崩溃**。事件日志实证：`flutter_windows.dll` 偏移 `0x1d7b0`，`0xc0000005` → 随后 `0xc000041d`。

链路：`AppTrayService.exitApp()` → `windowManager.destroy()`，其原生实现（window_manager_plugin `WindowManager::Destroy()`）只有 `PostQuitMessage(0)`，**窗口压根没销毁** → main.cpp 消息循环退出 → `::CoUninitialize()` → main 返回时栈对象 `~FlutterWindow` 才析构引擎 → 引擎与 WebView2 在 **COM 已卸载**的线程上销毁 → AV → WER 挂起全线程收 dump（这 13~19s 就是 dump 时间）。

官方模板没这问题是因为正常关闭走 WM_CLOSE → DestroyWindow → WM_DESTROY（OnDestroy 已释放引擎）→ PostQuitMessage，析构天然在 CoUninitialize 之前。

**改动**：
1. `windows/runner/main.cpp`：消息循环后、`CoUninitialize()` 前显式 `window.Destroy()`。
2. `windows/runner/flutter_window.cpp` `OnDestroy()`：补 reset `dynamic_island_window_`/`agent_profile_window_`；controller 销毁后 `SetChildContent(nullptr)`（显式销毁路径下主窗口还活着，防 child_content_ 悬垂）。
3. `lib/core/services/app_tray_service.dart` `exitApp()`：改走 `windowManager.close()`（标准 WM_CLOSE 链路），去掉多余的 `setSkipTaskbar(false)`，摘托盘图标，加 `_exiting` 重入 guard，800ms 后 destroy + 400ms 后 exit(0) 兜底。

**验证**（release 构建，部署到 `D:\Nextbot`，旧 exe/app.so 备份在 `logs/backup-20261020/`）：
- 空态：19570ms → **76ms**，0 崩溃事件。
- 真实态（173MB / 87 线程 / 6 个 msedgewebview2 子进程）：**524ms**，0 崩溃事件。

**副作用记录**：崩溃退出会留下 `Threads=0` 的僵尸进程对象，占用 exe 映像导致覆盖报 busy —— **Git Bash 的 `cp` 报 `Device or resource busy`，PowerShell `Copy-Item -Force` 能成功**。`flutter build windows` 退出码 1 是 cmake_install 到 windows_dist 失败（MSB3073），build 目录产物本身是新的。

顺手把 MEMORY.md 从 23.8KB 压到 10.7KB（原文件超注入上限被截断）。

## 启动白屏（Debug 版）根因修复

用户报「还有白屏了」。实测连拍（`logs/burst-capture.ps1`，每 300ms 抓窗口 + 算平均亮度）定位：

- **Release 版不白屏**：窗口 801ms 出现，首个可见帧亮度 19（深色加载页：黑底 + 暗 N logo）。
- **Debug 版白屏**：窗口 3254ms 出现时亮度 **219.9（接近纯白）**，直到 4662ms 才变黑 → 纯白持续约 1.4 秒。

**根因**：`main.dart` 的 `WindowOptions(backgroundColor: Colors.transparent)`。窗口在 `runApp` **之前**就 `show()` 了（`waitUntilReadyToShow` 回调里），此时首帧未渲染；Windows 上 Flutter 不支持逐像素透明，`transparent` 被 DWM 填成**白色客户区**。Release 引擎初始化快（40ms 内出首帧）所以看不出来，Debug 走 JIT 加载 86MB kernel_blob 慢，白窗就被放大成肉眼可见的白屏。

**修法**：`backgroundColor: AppPalette.mainPanel`（= `0xFF0F0F0F`，与主面板/加载页同色）。注意颜色常量在 `AppPalette` 不是 `AppTheme`（`AppTheme` 只有 `ThemeData`）。

**验证**：Debug 版首个可见帧 219.9 → **20.5**，窗口出现 3254ms → 1920ms（kernel 缓存热）；退出 515ms、0 崩溃事件。

**部署范围**（两处都更新，旧产物备份在 `logs/backup-20261020/`）：
- `D:\Nextbot` + `windows_dist\Release`：exe 22:47（退出修复）+ app.so 22:58（白屏修复）。
- `windows_dist\Debug`：整套 robocopy（exe 23:00 + kernel_blob 22:59）；Debug 的 Dart 代码在 kernel_blob 里，**只换 exe 不换 kernel_blob 等于没改**。

**排查手法留存**：`CopyFromScreen` 抓的是屏幕像素（会被上层窗口遮挡误导），`PrintWindow(PW_RENDERFULLCONTENT)` 抓窗口自身内容但读的是 DWM 缓存（hide/show 后看不出是否重绘）。判断「是否白屏」用**平均亮度**最可靠：正常深色 UI ≈ 19~26，白屏 ≈ 220。
