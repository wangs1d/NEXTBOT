语音通道 × Agent 大脑：解耦选型脑图

核心问题：端到端语音模型把 ASR/LLM/TTS 焊死，Agent 的记忆、工具、人格被绕过 ｜ 评估时间 2026-10

  • 语音 × Agent 解耦
    外看端到端 · 内看全可拆
    • ★ 最优落地：双层解耦
      针对 NextBot（记忆 / Tool Routing / MCP / Windows）
      • 入口网关：Qwen-Audio-Agent，Windows 悬浮 Orb 现成
      • 本地语音引擎：HF speech-to-speech，全链路本地
      • LLM 段 → NextBot 的 OpenAI 兼容端点（人格 / 记忆 100% 自有）
      • 长任务后端 → NextBot ACP stdio（复用 MCP / Skills / 认证）
      • 中文组件：Paraformer STT ＋ Qwen3-TTS / VoxCPM ＋ Silero VAD
      • 底层模型可云端，但必经 NextBot，不再被语音模型内置 LLM 截胡
    • 范式 B · Harness 编排层
      语音是前端，干活的是你自己的 Agent
      • Qwen-Audio-Agent ｜ Apache-2.0 ｜ TypeScript/Node
      • 语音前端可换：Qwen / GPT-Live / Gemini / 豆包 Seeduplex / Step / 本地
      • 后端经 ACP / A2A 接任意 Agent（通用 ACP_COMMAND 接入）
      • 前台对话 ‖ 后台任务并行，结果自然回流，可追问 / 取消
      • 自带跨会话记忆、知识库、前端工具、桌面端（Win/macOS/Linux）
      • 分工：ACP 管 Agent 会话/权限，MCP 管工具/资源
    • 范式 A · 协议标准化引擎
      用 OpenAI Realtime 协议把语音 IO 服务器化
      • HuggingFace speech-to-speech ｜ Apache-2.0 ｜ Python 3.10+
      • VAD → STT → LLM → TTS，四段逐可换，CLI flag 切换
      • 对外仅一个 OpenAI Realtime 兼容 WebSocket（/v1/realtime）
      • 默认全本地：llama.cpp / vLLM / mlx-lm，客户端零改动
      • 工具事件透传——工具能力由 LLM 端（NextBot）决定
      • 代价：级联而非神经 E2E，延迟与运维自己扛（已量产于 Reachy Mini）
    • 范式 C · 端到端可拆模型
      组件独立训练，但换大脑仍需训练
      • NemotronLabs VoiceChat（NVIDIA, 2026-09）｜ CC BY 4.0
      • FastConformer ＋ Nemotron-Nano-9B ＋ 独立流式 TTS，全双工
      • 并行专用 function channel，工具选择 F1 82.5%（超 Gemini Live）
      • 换 LLM 需 CPT/SFT（64×GPU 级），非“随意适配”
      • 限制：2 分钟记忆窗口 ｜ ≤5 工具 ｜ 工具执行中不可打断
      • 端到端族（换脑均需训练）：Moshi / Smallthinker、Step-Audio 2、VITA-Audio / QinYu、MiniCPM-o 4.5
    • 备选编排框架
      按技术栈 / 部署形态取舍
      • Pipecat ｜ BSD-2 ｜ Python：帧 Pipeline，插入粒度最细，全 Python 首选
      • LiveKit Agents ｜ Apache-2.0 ｜ Py/Node：WebRTC/SFU、高并发、SIP 电话
      • TEN Framework（声网）：C++ 扩展图、边缘低延迟，Smart Turn 全开源含训练数据
核心判断：“神经端到端 ＋ 中间 LLM 零成本热替换”在工程上不成立——音频 token 空间与 LLM 联合训练，换脑必有适配训练。 2026 年开源界的实际答案是把解耦上移两层：引擎层用 OpenAI Realtime 协议把语音 IO 服务器化、四段可换（speech-to-speech）； Harness 层把实时语音前端与执行型 Agent 用 ACP/A2A 分开，并解决 Agent 干活时对话“在场”的问题（Qwen-Audio-Agent）。 对 NextBot：Qwen-Audio-Agent ＋ 本地 speech-to-speech（LLM 段指向 NextBot）＋ NextBot 作 ACP 后端为当前最优组合； 想先跑通 MVP 可只用 speech-to-speech，想全 Python 深度内嵌则用 Pipecat。
